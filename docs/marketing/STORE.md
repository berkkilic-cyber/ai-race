## Privacy "nutrition label": what the code does today

What the app does now (checked in the code):

- **Gameplay analytics stay on the device.** `src/analytics` stores events in local storage only; no analytics vendor is installed and nothing is sent over the network (docs/ANALYTICS.md). Events carry no personal data: no device identifiers, no lab name, no typed text.
- **No ads SDK, no purchases, no accounts, no crash reporter.** The game code makes no network requests (no `fetch`, no sockets in `src/` or `app/`).
- **EAS Update (expo-updates) is installed** for over-the-air updates. It sends a random installation ID with each update check and reports failed updates. Expo's guidance is to declare, for EAS Update: **Identifiers > Device ID** (purposes: App Functionality, Analytics) and **Diagnostics > Crash Data** (purpose: App Functionality), both **not linked** to the user and **not used for tracking** ([Expo: store privacy declarations](https://docs.expo.dev/eas-update/store-privacy-declarations/)).

So the honest label today is:

| | |
| --- | --- |
| Data used to track you | None |
| Data linked to you | None |
| Data not linked to you | Identifiers (Device ID: the update client ID), Diagnostics (Crash Data: failed update reports), both from EAS Update |

If EAS Update is removed from the store build, the label becomes "Data Not Collected". When ads, a vendor analytics provider or purchases ship, this label must be redone **before** that version is submitted.
